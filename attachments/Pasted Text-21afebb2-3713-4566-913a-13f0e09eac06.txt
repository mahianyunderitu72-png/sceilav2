SCEILA
a sailor always carry things in a set of three. if one carries one compass and it is broken, they will get lost, if they carry 2 and one is broken and another is faulty, they will get confused, if they carry 3 compasses, they can always count on the two that points on the same direction
for users, we give the compasses in this sea of information that is becoming increasingly hard to tell the truth from fake.

main goal - democratization of agents ( anyone can own their agents) and availability of many agents, giving agents identity( ERC 721) and financial capabilities (erc 6551)

STABLECOINS- used for staking, governance, treasury- protocol growth. main purpose is agents should stake for a task to act as a custodian of truth- if they perform well they earn more tokens, otherwise slashed. the token acts as a unified financial layer to prevent agents from staking in different currency

PROTOCOL
agents are connected to the protocol via a wallet since they are represented by nft. the owner connects the wallet containing the agents, the protocol reads the agent's nft for api endpoint, description, skills and name and connects to the agents, and create a reputation database that will be updated everytime the agents performs tasks

agent identity- for those with agents without identity, the protocol creates the identity for them with them providing the necessary info like agent name, description, skills, and api endpoint which are stored in IPFS database to get metadata URI and wallet address that will then be used to generate ERC 721 nft representing the ownership

Buoys- this allows people with no coding skills to create agents by selecting templates, selecting tools they want the agents to use and add API keys from other models to make the agents more powerful. and these agents are also given identity and managed by the users. the users could use them directly for their tasks or use them to earn from the protocol

Chat- users could use the protocal as any other chat bot, have conversations, access previous chats, and general tasks. inspired by claude ai, we could have project where one could upload files and instruction, create skills and have chats under the project

Miniapps- developers could create miniapps that uses the protocol's Agents to do tasks. the miniapps are more specialized for example, miniapps for accounting, ERP, Humanizing, Video generation, Coding, Academics, Design, etc. these mostly contributes to the demand side of the protocol

Orchestrator- the main part of the protocol- it receives tasks and instructions from users and miniapps, selects qualified agents, gives the task and coordinate the agents to get optimum/best solution, score the agents( reputation) which will be used to award or slash the agents

Tools- these are programs for agents to use like RAG, MCP, telegram, message, email, whatsapp, spreadsheet, github, web, agent to agent communication( necessary if agents wants to collaborate), etc.

marketplace- here people list agents for sale or lease and people can view them buy or hire agents and their description and reputation and prices. agents can also hire agents

unified payment- since most miniapp and agents are free, the uses need not have wallets and could pay for agents, miniapps or/ and tasks. instead of paying each indepedently, you pay all at one. agents owners must have wallets( they hold agents). the system allows the user to pay with the utility token directly or any currency but agents are paid only with the utility token. miniapps- are paid in however they want but preferrably with the utility token which is fast to settle.

 unified Protocol API, developer sdk- this allows developers to use the protocol in their apps via sdk or api.


the frontend should have chat ( new or history), miniapps, attach wallet, register agent, create a buoys, protocol news, governance, about, academy, dashboard ( to manage tasks and agents), marketplace, explore, etc. chat and miniapp are the focal point to guide users to them.

BUOY
I want to clone openrouter. Not exactly, but the idea of aggregating AI providers and have one unified API and billing. The context is, a platform to allow people with no code skills to create simple AI agents in about five steps. 
Step 1. Select a template. Each template presents a code block, and depending on the task the agent is to perform.
Step 2. Select tools. Tools are what gives agents abilities to act. Examples of tools includes RAG, mcp, telegram, calendar, email, etc
Step 3. Select/create skills. Skills are instructions or context for agents to follow. Example is a humanizing skills, a coding skill, a presentation skill, etc
Step 4. Select models. Model are LLMs that the agent will use. Users select all model that are required and preferably more than one so that when one hit API call limit, the other is used
Step 5. Create the agent. An agent made of the template codeblock, tools, skills, model is used. We call this agent a buoy.

At step 4, if where inspiration from open router comes from. At step 4, we give the buoy one unified API but below that is all the selected LLMs. The main problem I encountered that stems from not fully understanding openrouter is the aggregation- like if 100 buoys select Gemini, or groq, how does the platform interact with Gemini - are we creating 100 APIs for every buoy, or just one and if it's one, won't API limits affect us because one API is being called 100 times. together with steps 1,2,3,5 of the buoys where in step 1 should allow addition of templates for different types of agents.
